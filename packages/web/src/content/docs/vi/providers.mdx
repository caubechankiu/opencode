OpenCode dùng [AI SDK](https://ai-sdk.dev/) và [Models.dev](https://models.dev) để hỗ trợ **hơn 75 nhà cung cấp LLM**, đồng thời hỗ trợ chạy mô hình cục bộ.

Để thêm một nhà cung cấp, bạn cần:

1. Thêm API keys cho nhà cung cấp bằng lệnh `/connect`.
2. Cấu hình nhà cung cấp trong cấu hình OpenCode của bạn.

---

### Thông tin xác thực

Khi bạn thêm API keys của một nhà cung cấp bằng lệnh `/connect`, chúng được lưu trong `~/.local/share/opencode/auth.json`.

---

### Cấu hình

Bạn có thể tùy chỉnh các nhà cung cấp thông qua phần `provider` trong cấu hình OpenCode.

---

#### Base URL

Bạn có thể tùy chỉnh base URL cho bất kỳ nhà cung cấp nào bằng cách đặt tùy chọn `baseURL`. Điều này hữu ích khi dùng dịch vụ proxy hoặc endpoint tùy chỉnh.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

---

#### Ẩn mô hình

Bạn có thể ẩn các mô hình cụ thể khỏi bộ chọn `/models` của một nhà cung cấp bằng tùy chọn `blacklist`. Điều này hữu ích khi nhà cung cấp hiển thị các mô hình bạn không muốn dùng hoặc chọn.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "blacklist": ["claude-opus-4-20250514"]
    }
  }
}
```

Tùy chọn ngược lại, `whitelist`, sẽ ẩn mọi mô hình ngoại trừ các mô hình được liệt kê.

```json title="opencode.json" {6}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "whitelist": ["claude-sonnet-4-20250514"]
    }
  }
}
```

Cả hai tùy chọn đều nhận một mảng model IDs — chính là các ID hiển thị trong bộ chọn `/models`.

- `blacklist` xóa các mô hình được liệt kê khỏi bộ chọn.
- `whitelist` chỉ giữ các mô hình được liệt kê và ẩn phần còn lại.
- Bạn có thể kết hợp chúng: `whitelist` thu hẹp tập hợp, rồi `blacklist` xóa các mục khỏi tập hợp đó.

## OpenCode Zen

OpenCode Zen là danh sách các mô hình do đội ngũ OpenCode cung cấp, đã được kiểm thử và xác minh là hoạt động tốt với OpenCode. [Tìm hiểu thêm](/docs/zen).

:::tip
Nếu bạn mới bắt đầu, chúng tôi khuyên nên khởi đầu với OpenCode Zen.
:::

1. Chạy lệnh `/connect` trong TUI, chọn `OpenCode Zen`, rồi truy cập [opencode.ai/auth](https://opencode.ai/zen).

   ```txt
   /connect
   ```

2. Đăng nhập, thêm thông tin thanh toán, rồi sao chép API key của bạn.

3. Dán API key của bạn.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. Chạy `/models` trong TUI để xem danh sách mô hình chúng tôi đề xuất.

   ```txt
   /models
   ```

Nó hoạt động như mọi nhà cung cấp khác trong OpenCode và hoàn toàn không bắt buộc dùng.

### Amazon Bedrock

Để dùng Amazon Bedrock với OpenCode:

1. Truy cập **Model catalog** trong Amazon Bedrock console và yêu cầu quyền truy cập các mô hình bạn muốn.

   :::tip
   Bạn cần có quyền truy cập mô hình mong muốn trong Amazon Bedrock.
   :::

2. **Cấu hình xác thực** bằng một trong các phương thức sau:

   ***

   #### Biến môi trường (bắt đầu nhanh)

   Đặt một trong các biến môi trường này khi chạy opencode:

   ```bash
   # Option 1: Using AWS access keys
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY opencode

   # Option 2: Using named AWS profile
   AWS_PROFILE=my-profile opencode

   # Option 3: Using Bedrock bearer token
   AWS_BEARER_TOKEN_BEDROCK=XXX opencode
   ```

   Hoặc thêm chúng vào bash profile của bạn:

   ```bash title="~/.bash_profile"
   export AWS_PROFILE=my-dev-profile
   export AWS_REGION=us-east-1
   ```

   ***

   #### Tệp cấu hình (khuyến nghị)

   Với cấu hình riêng cho dự án hoặc cấu hình lâu dài, dùng `opencode.json`:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "my-aws-profile"
         }
       }
     }
   }
   ```

   **Tùy chọn khả dụng:**
   - `region` - AWS region (ví dụ `us-east-1`, `eu-west-1`)
   - `profile` - AWS named profile từ `~/.aws/credentials`
   - `endpoint` - URL endpoint tùy chỉnh cho VPC endpoints (alias cho tùy chọn chung `baseURL`)

   :::tip
   Tùy chọn trong tệp cấu hình được ưu tiên hơn biến môi trường.
   :::

   ***

   #### Nâng cao: VPC Endpoints

   Nếu bạn đang dùng VPC endpoints cho Bedrock:

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "production",
           "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
         }
       }
     }
   }
   ```

   :::note
   Tùy chọn `endpoint` là alias cho tùy chọn chung `baseURL`, dùng thuật ngữ riêng của AWS. Nếu cả `endpoint` và `baseURL` đều được chỉ định, `endpoint` được ưu tiên.
   :::

   ***

   #### Phương thức xác thực
   - **`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`**: Tạo IAM user và tạo access keys trong AWS Console
   - **`AWS_PROFILE`**: Dùng named profiles từ `~/.aws/credentials`. Trước tiên cấu hình bằng `aws configure --profile my-profile` hoặc `aws sso login`
   - **`AWS_BEARER_TOKEN_BEDROCK`**: Tạo API keys dài hạn từ Amazon Bedrock console
   - **`AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_ARN`**: Dành cho EKS IRSA (IAM Roles for Service Accounts) hoặc môi trường Kubernetes khác có OIDC federation. Các biến môi trường này được Kubernetes tự động inject khi dùng service account annotations.

   ***

   #### Thứ tự ưu tiên xác thực

   Amazon Bedrock dùng thứ tự ưu tiên xác thực sau:
   1. **Bearer Token** - biến môi trường `AWS_BEARER_TOKEN_BEDROCK` hoặc token từ lệnh `/connect`
   2. **AWS Credential Chain** - Profile, access keys, shared credentials, IAM roles, Web Identity Tokens (EKS IRSA), instance metadata

   :::note
   Khi bearer token được đặt (qua `/connect` hoặc `AWS_BEARER_TOKEN_BEDROCK`), nó được ưu tiên hơn mọi phương thức AWS credential, bao gồm cả profiles đã cấu hình.
   :::

3. Chạy lệnh `/models` để chọn mô hình bạn muốn.

   ```txt
   /models
   ```

:::note
Với custom inference profiles, hãy dùng tên mô hình và nhà cung cấp trong khóa rồi đặt thuộc tính `id` thành arn. Điều này đảm bảo cache chính xác.
:::

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      // ...
      "models": {
        "anthropic-claude-sonnet-4.5": {
          "id": "arn:aws:bedrock:us-east-1:xxx:application-inference-profile/yyy"
        }
      }
    }
  }
}
```

### Atomic Chat

Bạn có thể cấu hình opencode để dùng mô hình cục bộ thông qua [Atomic Chat](https://atomic.chat), một ứng dụng desktop chạy LLM cục bộ phía sau máy chủ API tương thích OpenAI (endpoint mặc định `http://127.0.0.1:1337/v1`).

```json title="opencode.json" "atomic-chat" {5, 6, 8, 10-14}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "atomic-chat": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Atomic Chat (local)",
      "options": {
        "baseURL": "http://127.0.0.1:1337/v1"
      },
      "models": {
        "<your-model-id>": {
          "name": "<your-model-name>"
        }
      }
    }
  }
}
```

Trong ví dụ này:

- `atomic-chat` là custom provider ID. Đây có thể là bất kỳ chuỗi nào bạn muốn.
- `npm` chỉ định package dùng cho nhà cung cấp này. Ở đây, `@ai-sdk/openai-compatible` được dùng cho mọi API tương thích OpenAI.
- `name` là tên hiển thị của nhà cung cấp trong UI.
- `options.baseURL` là endpoint cho máy chủ cục bộ. Change the host and port to match your Atomic Chat setup.
- `models` là map từ model IDs tới tên hiển thị. Mỗi ID phải khớp với `id` do `GET /v1/models` trả về — chạy `curl http://127.0.0.1:1337/v1/models` để liệt kê các ids hiện được tải trong Atomic Chat.

:::tip
Nếu tool calls không hoạt động tốt, hãy chọn một mô hình đã tải có hỗ trợ tool-calling mạnh (ví dụ một biến thể Qwen-Coder hoặc DeepSeek-Coder).
:::

### Azure OpenAI

:::note
Nếu gặp lỗi "I'm sorry, but I cannot assist with that request", hãy thử đổi content filter từ **DefaultV2** sang **Default** trong Azure resource của bạn.
:::

1. Truy cập [Azure portal](https://portal.azure.com/) và tạo một **Azure OpenAI** resource. Bạn sẽ cần:
   - **Resource name**: Giá trị này trở thành một phần của API endpoint (`https://RESOURCE_NAME.openai.azure.com/`)
   - **API key**: `KEY 1` hoặc `KEY 2` từ resource của bạn

2. Đi tới [Azure AI Foundry](https://ai.azure.com/) và deploy một mô hình.

   :::note
   Deployment name phải khớp với model name để opencode hoạt động đúng.
   :::

3. Chạy lệnh `/connect` và tìm **Azure**.

   ```txt
   /connect
   ```

4. Nhập API key của bạn.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

5. Đặt resource name của bạn làm biến môi trường:

   ```bash
   AZURE_RESOURCE_NAME=XXX opencode
   ```

   Hoặc thêm nó vào bash profile của bạn:

   ```bash title="~/.bash_profile"
   export AZURE_RESOURCE_NAME=XXX
   ```

6. Chạy lệnh `/models` để chọn mô hình đã deploy.

   ```txt
   /models
   ```

### Cloudflare AI Gateway

Cloudflare AI Gateway cho phép bạn truy cập các mô hình từ OpenAI, Anthropic, Workers AI, và nhiều nhà cung cấp khác thông qua một endpoint hợp nhất. Với [Unified Billing](https://developers.cloudflare.com/ai-gateway/features/unified-billing/), bạn không cần API keys riêng cho từng nhà cung cấp.

1. Truy cập [Cloudflare dashboard](https://dash.cloudflare.com/), đi tới **AI** > **AI Gateway**, rồi tạo gateway mới. Ghi lại **Account ID** và **Gateway ID**.

2. Chạy lệnh `/connect` và tìm **Cloudflare AI Gateway**.

   ```txt
   /connect
   ```

3. Nhập **Account ID** của bạn khi được nhắc.

   ```txt
   ┌ Enter your Cloudflare Account ID
   │
   │
   └ enter
   ```

4. Nhập **Gateway ID** của bạn khi được nhắc.

   ```txt
   ┌ Enter your Cloudflare AI Gateway ID
   │
   │
   └ enter
   ```

5. Nhập **Cloudflare API token** của bạn.

   ```txt
   ┌ Gateway API token
   │
   │
   └ enter
   ```

6. Chạy lệnh `/models` để chọn mô hình.

   ```txt
   /models
   ```

   Bạn cũng có thể thêm mô hình thông qua cấu hình opencode.

   ```json title="opencode.json"
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "cloudflare-ai-gateway": {
         "models": {
           "openai/gpt-4o": {},
           "anthropic/claude-sonnet-4": {}
         }
       }
     }
   }
   ```

   Ngoài ra, bạn có thể đặt biến môi trường thay vì dùng `/connect`.

   ```bash title="~/.bash_profile"
   export CLOUDFLARE_ACCOUNT_ID=your-32-character-account-id
   export CLOUDFLARE_GATEWAY_ID=your-gateway-id
   export CLOUDFLARE_API_TOKEN=your-api-token
   ```

##### GitLab Duo Agent Platform (DAP) Workflow Models

Các mô hình DAP workflow cung cấp một đường thực thi thay thế, định tuyến tool calls qua Duo Workflow Service (DWS) của GitLab thay vì agentic chat tiêu chuẩn. Khi chọn một mô hình `duo-workflow-*`, OpenCode sẽ:

1. Phát hiện các mô hình khả dụng từ GitLab namespace của bạn
2. Hiển thị bộ chọn nếu có nhiều mô hình khả dụng
3. Cache mô hình đã chọn vào ổ đĩa để các lần khởi động sau nhanh hơn
4. Định tuyến yêu cầu thực thi công cụ qua hệ thống công cụ có kiểm soát quyền của OpenCode

Các mô hình DAP workflow khả dụng tuân theo quy ước đặt tên `duo-workflow-*` và được phát hiện động từ GitLab instance của bạn.

#### Cấu hình tùy chọn

Nếu bạn thấy một tính năng hoặc mô hình từ Helicone chưa được cấu hình tự động qua opencode, bạn luôn có thể tự cấu hình.

Đây là [Helicone's Model Directory](https://helicone.ai/models); bạn sẽ cần nó để lấy ID của các mô hình muốn thêm.

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
      },
      "models": {
        "gpt-4o": {
          // Model ID (from Helicone's model directory page)
          "name": "GPT-4o", // Your own custom name for the model
        },
        "claude-sonnet-4-20250514": {
          "name": "Claude Sonnet 4",
        },
      },
    },
  },
}
```

#### Headers tùy chỉnh

Helicone hỗ trợ headers tùy chỉnh cho các tính năng như caching, theo dõi người dùng, và quản lý phiên. Thêm chúng vào cấu hình nhà cung cấp bằng `options.headers`:

```jsonc title="~/.config/opencode/opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "opencode",
        },
      },
    },
  },
}
```

##### Theo dõi phiên

Tính năng [Sessions](https://docs.helicone.ai/features/sessions) của Helicone cho phép bạn nhóm các yêu cầu LLM liên quan lại với nhau. Dùng plugin [opencode-helicone-session](https://github.com/H2Shami/opencode-helicone-session) để tự động ghi log mỗi cuộc trò chuyện OpenCode thành một session trong Helicone.

```bash
npm install -g opencode-helicone-session
```

Thêm nó vào cấu hình của bạn.

```json title="opencode.json"
{
  "plugin": ["opencode-helicone-session"]
}
```

Plugin inject các header `Helicone-Session-Id` và `Helicone-Session-Name` vào yêu cầu của bạn. Trong trang Sessions của Helicone, bạn sẽ thấy mỗi cuộc trò chuyện OpenCode được liệt kê như một session riêng.

##### Headers Helicone thường dùng

| Header                     | Mô tả                                                         |
| -------------------------- | ------------------------------------------------------------- |
| `Helicone-Cache-Enabled`   | Bật response caching (`true`/`false`)                         |
| `Helicone-User-Id`         | Theo dõi metrics theo người dùng                              |
| `Helicone-Property-[Name]` | Thêm properties tùy chỉnh (ví dụ `Helicone-Property-Environment`) |
| `Helicone-Prompt-Id`       | Liên kết yêu cầu với các phiên bản prompt                     |

Xem [Helicone Header Directory](https://docs.helicone.ai/helicone-headers/header-directory) để biết tất cả headers khả dụng.

### Snowflake Cortex

Chưa có tài khoản Snowflake? [Đăng ký dùng thử miễn phí](https://signup.snowflake.com/?utm_source=opencode&utm_medium=docs&utm_campaign=cortex-provider).

Workflow cốt lõi của opencode cho viết mã, sửa tệp, và chạy lệnh phụ thuộc vào tool calling. Chỉ các họ Claude và OpenAI trong Snowflake Cortex hỗ trợ điều này. Nhà cung cấp này được giới hạn ở các họ đó để hỗ trợ workflow cốt lõi.

OpenCode hỗ trợ hai phương thức xác thực:

- **Browser OAuth (Recommended)** — đăng nhập bằng IdP/SSO của bạn; không cần quản lý secret, token tự động refresh.
- **Manual bearer token** — dán PAT hoặc JWT từ Snowflake console.

#### Browser OAuth (Recommended)

1. Chạy lệnh `/connect` và tìm **Snowflake Cortex**.

   ```txt
   /connect
   ```

2. Chọn **Login with Snowflake (External Browser)**.

   ```txt
   ┌ Select auth method
   │
   │ Login with Snowflake (External Browser)
   │ Paste PAT or bearer token manually
   └
   ```

3. Nhập [account identifier](https://docs.snowflake.com/en/user-guide/admin-account-identifier) khi được nhắc, ví dụ `myorg-myaccount` hoặc `xy12345.us-east-1`.

   ```txt
   ┌ Snowflake Account Identifier
   │
   │
   └ enter
   ```

4. Tùy chọn nhập Snowflake role để giới hạn phạm vi phiên (ví dụ `SYSADMIN`). Để trống để dùng role mặc định.

5. Hoàn tất đăng nhập trong trình duyệt mở ra. OpenCode tự động bắt OAuth callback và lưu token — không cần copy/paste.

6. Chạy lệnh `/models` để chọn mô hình.

   ```txt
   /models
   ```

:::note
Browser OAuth dùng security integration tích hợp sẵn `SNOWFLAKE$LOCAL_APPLICATION` của Snowflake ([docs](https://docs.snowflake.com/en/user-guide/oauth-local-applications)), đang được triển khai tới mọi tài khoản. Để kiểm tra khả dụng trong tài khoản của bạn:

```sql
SHOW SECURITY INTEGRATIONS LIKE 'SNOWFLAKE$LOCAL_APPLICATION';
```

Nếu kết quả trống, hãy dùng phương thức **Manual bearer token** bên dưới trong khi integration được triển khai tới tài khoản của bạn.
:::

#### Manual bearer token

Nếu bạn muốn dán token trực tiếp, hoặc nếu `SNOWFLAKE$LOCAL_APPLICATION` chưa khả dụng trong tài khoản của bạn:

1. Tạo [Programmatic Access Token (PAT)](https://docs.snowflake.com/en/user-guide/programmatic-access-tokens) trong tài khoản Snowflake của bạn.

2. Chạy lệnh `/connect`, tìm **Snowflake Cortex**, rồi chọn **Paste PAT or bearer token manually**.

3. Nhập [account identifier](https://docs.snowflake.com/en/user-guide/admin-account-identifier) khi được nhắc.

4. Dán PAT của bạn.

5. Chạy lệnh `/models` để chọn mô hình.

   ```txt
   /models
   ```

#### Biến môi trường

Với môi trường CI hoặc headless, đặt PAT hoặc JWT trước khi khởi động opencode:

```bash
export SNOWFLAKE_ACCOUNT=myorg-myaccount
export SNOWFLAKE_CORTEX_TOKEN=your-pat-or-jwt
```

:::note
`SNOWFLAKE_CORTEX_TOKEN` chỉ chấp nhận PAT hoặc JWT — luồng browser OAuth chỉ khả dụng qua `/connect` và không thể cấu hình bằng biến môi trường. `SNOWFLAKE_CORTEX_PAT` vẫn được hỗ trợ để tương thích ngược.

Có ba cách xác thực: gói đăng ký SuperGrok qua browser OAuth, cùng gói SuperGrok đó qua luồng device-code headless (cho VPS / SSH / Docker), hoặc API key trả theo mức dùng từ xAI console.

## Nhà cung cấp tùy chỉnh

Để thêm bất kỳ nhà cung cấp **tương thích OpenAI** nào không có trong lệnh `/connect`:

:::tip
Bạn có thể dùng bất kỳ nhà cung cấp tương thích OpenAI nào với opencode. Hầu hết nhà cung cấp AI hiện đại đều cung cấp API tương thích OpenAI.
:::

1. Chạy lệnh `/connect` và cuộn xuống **Other**.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◆  Select provider
   │  ...
   │  ● Other
   └
   ```

2. Nhập một ID duy nhất cho nhà cung cấp.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◇  Enter provider id
   │  myprovider
   └
   ```

   :::note
   Chọn một ID dễ nhớ; bạn sẽ dùng nó trong tệp cấu hình.
   :::

3. Nhập API key của bạn cho nhà cung cấp.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ▲  This only stores a credential for myprovider - you will need to configure it in opencode.json, check the docs for examples.
   │
   ◇  Enter your API key
   │  sk-...
   └
   ```

4. Tạo hoặc cập nhật tệp `opencode.json` trong thư mục dự án:

   ```json title="opencode.json" ""myprovider"" {5-15}
   {
     "$schema": "https://opencode.ai/config.json",
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "My AI ProviderDisplay Name",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "My Model Display Name"
           }
         }
       }
     }
   }
   ```

   Các tùy chọn cấu hình gồm:
   - **npm**: Package AI SDK cần dùng, `@ai-sdk/openai-compatible` cho nhà cung cấp tương thích OpenAI (cho `/v1/chat/completions`). Nếu nhà cung cấp/mô hình của bạn dùng `/v1/responses`, hãy dùng `@ai-sdk/openai`.
   - **name**: Tên hiển thị trong UI.
   - **models**: Các mô hình khả dụng.
   - **options.baseURL**: URL API endpoint.
   - **options.apiKey**: Tùy chọn đặt API key, nếu không dùng auth.
   - **options.headers**: Tùy chọn đặt headers tùy chỉnh.

   Xem thêm về các tùy chọn nâng cao trong ví dụ bên dưới.

5. Chạy lệnh `/models`; nhà cung cấp và mô hình tùy chỉnh của bạn sẽ xuất hiện trong danh sách chọn.

---

##### Ví dụ

Dưới đây là ví dụ đặt các tùy chọn `apiKey`, `headers`, và `limit` của mô hình.

```json title="opencode.json" {9,11,17-20}
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My AI ProviderDisplay Name",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "My Model Display Name",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

Chi tiết cấu hình:

- **apiKey**: Đặt bằng cú pháp biến `env`, [tìm hiểu thêm](/docs/config#env-vars).
- **headers**: Headers tùy chỉnh được gửi với mỗi yêu cầu.
- **limit.context**: Số input tokens tối đa mà mô hình chấp nhận.
- **limit.output**: Số tokens tối đa mà mô hình có thể tạo.

Các trường `limit` cho phép OpenCode biết bạn còn bao nhiêu ngữ cảnh. Nhà cung cấp tiêu chuẩn tự động lấy các giá trị này từ models.dev.

## Khắc phục sự cố

Nếu bạn gặp khó khăn khi cấu hình nhà cung cấp, hãy kiểm tra các mục sau:

1. **Kiểm tra thiết lập auth**: Chạy `opencode auth list` để xem thông tin xác thực cho nhà cung cấp đã được thêm vào cấu hình của bạn chưa.

   Điều này không áp dụng cho các nhà cung cấp như Amazon Bedrock, vốn dựa vào biến môi trường để xác thực.

2. Với nhà cung cấp tùy chỉnh, kiểm tra cấu hình opencode và:
   - Đảm bảo provider ID dùng trong lệnh `/connect` khớp với ID trong cấu hình opencode.
   - Dùng đúng npm package cho nhà cung cấp. Ví dụ, dùng `@ai-sdk/cerebras` cho Cerebras. Với tất cả nhà cung cấp tương thích OpenAI khác, dùng `@ai-sdk/openai-compatible` (cho `/v1/chat/completions`); nếu một mô hình dùng `/v1/responses`, dùng `@ai-sdk/openai`. Với thiết lập pha trộn trong cùng một nhà cung cấp, bạn có thể ghi đè theo từng mô hình qua `provider.npm`.
   - Kiểm tra API endpoint đúng được dùng trong trường `options.baseURL`.
