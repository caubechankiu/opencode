description: Quản lý các công cụ mà LLM có thể dùng.
---

Công cụ cho phép LLM thực hiện hành động trong codebase của bạn. OpenCode đi kèm một bộ công cụ tích hợp sẵn, nhưng bạn có thể mở rộng bằng [custom tools](/docs/custom-tools) hoặc [MCP servers](/docs/mcp-servers).

Theo mặc định, tất cả công cụ đều được **bật** và không cần quyền để chạy. Bạn có thể kiểm soát hành vi công cụ thông qua [permissions](/docs/permissions).

---

## Cấu hình

Dùng trường `permission` để kiểm soát hành vi công cụ. Bạn có thể cho phép, từ chối, hoặc yêu cầu phê duyệt cho từng công cụ.

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "deny",
    "bash": "ask",
    "webfetch": "allow"
  }
}
```

Bạn cũng có thể dùng wildcard để kiểm soát nhiều công cụ cùng lúc. Ví dụ, để yêu cầu phê duyệt cho tất cả công cụ từ một MCP server:

```json title="opencode.json"
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "mymcp_*": "ask"
  }
}
```

[Tìm hiểu thêm](/docs/permissions) về cách cấu hình quyền.

## Tích hợp sẵn

Dưới đây là tất cả công cụ tích hợp sẵn có trong OpenCode.

---

### bash

Thực thi lệnh shell trong môi trường dự án của bạn.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": "allow"
  }
}
```

Công cụ này cho phép LLM chạy các lệnh terminal như `npm install`, `git status`, hoặc bất kỳ lệnh shell nào khác.

---

### edit

Sửa đổi tệp hiện có bằng cách thay thế chuỗi chính xác.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

Công cụ này chỉnh sửa tệp chính xác bằng cách thay thế các đoạn văn bản khớp chính xác. Đây là cách chính để LLM sửa code.

---

### write

Tạo tệp mới hoặc ghi đè tệp hiện có.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

Dùng mục này để cho phép LLM tạo tệp mới. Nó sẽ ghi đè các tệp hiện có nếu chúng đã tồn tại.

:::note
Công cụ `write` được kiểm soát bởi quyền `edit`, quyền này bao gồm mọi sửa đổi tệp (`edit`, `write`, `apply_patch`).
:::

---

### read

Đọc nội dung tệp từ codebase của bạn.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "read": "allow"
  }
}
```

Công cụ này đọc tệp và trả về nội dung của chúng. Nó hỗ trợ đọc các khoảng dòng cụ thể cho tệp lớn.

---

### grep

Tìm kiếm nội dung tệp bằng biểu thức chính quy.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "grep": "allow"
  }
}
```

Tìm kiếm nội dung nhanh trên toàn codebase. Hỗ trợ đầy đủ cú pháp regex và lọc theo pattern tệp.

---

### glob

Tìm tệp bằng khớp pattern.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "glob": "allow"
  }
}
```

Tìm tệp bằng glob pattern như `**/*.js` hoặc `src/**/*.ts`. Trả về các đường dẫn tệp khớp được sắp xếp theo thời gian sửa đổi.

---

### lsp (experimental)

Tương tác với các máy chủ LSP đã cấu hình để nhận tính năng hiểu code như định nghĩa, tham chiếu, thông tin hover, và call hierarchy.

:::note
Công cụ này chỉ khả dụng khi `OPENCODE_EXPERIMENTAL_LSP_TOOL=true` (hoặc `OPENCODE_EXPERIMENTAL=true`).
:::

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "lsp": "allow"
  }
}
```

Các thao tác được hỗ trợ gồm `goToDefinition`, `findReferences`, `hover`, `documentSymbol`, `workspaceSymbol`, `goToImplementation`, `prepareCallHierarchy`, `incomingCalls`, và `outgoingCalls`.

Để cấu hình máy chủ LSP nào khả dụng cho dự án của bạn, xem [LSP Servers](/docs/lsp).

---

### apply_patch

Áp dụng patch vào tệp.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "allow"
  }
}
```

Công cụ này áp dụng các tệp patch vào codebase của bạn. Hữu ích để áp dụng diff và patch từ nhiều nguồn.

Khi xử lý hook `tool.execute.before` hoặc `tool.execute.after`, hãy kiểm tra `input.tool === "apply_patch"` (không phải `"patch"`).

`apply_patch` dùng `output.args.patchText` thay vì `output.args.filePath`. Đường dẫn được nhúng trong các dòng marker bên trong `patchText` và tương đối với thư mục gốc của dự án (ví dụ: `*** Add File: src/new-file.ts`, `*** Update File: src/existing.ts`, `*** Move to: src/renamed.ts`, `*** Delete File: src/obsolete.ts`).

:::note
Công cụ `apply_patch` được kiểm soát bởi quyền `edit`, quyền này bao gồm mọi sửa đổi tệp (`edit`, `write`, `apply_patch`).
:::

---

### skill

Tải một [skill](/docs/skills) (tệp `SKILL.md`) và trả nội dung của nó vào cuộc trò chuyện.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "skill": "allow"
  }
}
```

---

### todowrite

Quản lý danh sách việc cần làm trong các phiên coding.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "todowrite": "allow"
  }
}
```

Tạo và cập nhật danh sách tác vụ để theo dõi tiến độ trong các thao tác phức tạp. LLM dùng công cụ này để tổ chức tác vụ nhiều bước.

:::note
Công cụ này bị tắt cho subagent theo mặc định, nhưng bạn có thể bật thủ công. [Tìm hiểu thêm](/docs/agents/#permissions)
:::

---

### webfetch

Lấy nội dung web.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "webfetch": "allow"
  }
}
```

Cho phép LLM lấy và đọc các trang web. Hữu ích để tra cứu tài liệu hoặc nghiên cứu tài nguyên trực tuyến.

---

### websearch

Tìm kiếm thông tin trên web.

:::note
Công cụ này chỉ khả dụng khi dùng OpenCode provider hoặc khi biến môi trường `OPENCODE_ENABLE_EXA` được đặt thành bất kỳ giá trị truthy nào (ví dụ `true` hoặc `1`).

Để bật khi khởi chạy OpenCode:

```bash
OPENCODE_ENABLE_EXA=1 opencode
```

:::

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "websearch": "allow"
  }
}
```

Thực hiện tìm kiếm web bằng Exa AI để tìm thông tin liên quan trực tuyến. Hữu ích để nghiên cứu chủ đề, tìm sự kiện hiện tại, hoặc thu thập thông tin vượt ngoài thời điểm cắt dữ liệu huấn luyện.

Không cần API key — công cụ kết nối trực tiếp tới dịch vụ MCP được Exa AI host mà không cần xác thực.

:::tip
Dùng `websearch` khi bạn cần tìm thông tin (discovery), và `webfetch` khi bạn cần lấy nội dung từ một URL cụ thể (retrieval).
:::

---

### question

Hỏi người dùng trong quá trình thực thi.

```json title="opencode.json" {4}
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "question": "allow"
  }
}
```

Công cụ này cho phép LLM hỏi người dùng trong khi thực hiện tác vụ. Nó hữu ích để:

- Thu thập sở thích hoặc yêu cầu của người dùng
- Làm rõ hướng dẫn mơ hồ
- Lấy quyết định về lựa chọn triển khai
- Đưa ra lựa chọn về hướng đi tiếp theo

Mỗi câu hỏi gồm header, nội dung câu hỏi, và danh sách tùy chọn. Người dùng có thể chọn từ các tùy chọn được cung cấp hoặc nhập câu trả lời tùy chỉnh. Khi có nhiều câu hỏi, người dùng có thể di chuyển giữa chúng trước khi gửi tất cả câu trả lời.

Custom tools cho phép bạn định nghĩa các hàm riêng mà LLM có thể gọi. Chúng được định nghĩa trong tệp cấu hình của bạn và có thể thực thi code tùy ý.

## MCP servers

MCP (Model Context Protocol) servers cho phép bạn tích hợp công cụ và dịch vụ bên ngoài. Điều này bao gồm truy cập cơ sở dữ liệu, tích hợp API, và dịch vụ bên thứ ba.

[Tìm hiểu thêm](/docs/mcp-servers) về cách cấu hình MCP servers.

## Nội bộ

Bên trong, các công cụ như `grep` và `glob` dùng [ripgrep](https://github.com/BurntSushi/ripgrep) ở tầng dưới. Theo mặc định, ripgrep tôn trọng pattern trong `.gitignore`, nghĩa là các tệp và thư mục được liệt kê trong `.gitignore` sẽ bị loại khỏi tìm kiếm và liệt kê.

---

### Pattern bỏ qua

Để bao gồm các tệp thường bị bỏ qua, tạo tệp `.ignore` ở thư mục gốc dự án. Tệp này có thể cho phép rõ ràng một số đường dẫn.

```text title=".ignore"
!node_modules/
!dist/
!build/
```

Ví dụ, tệp `.ignore` này cho phép ripgrep tìm kiếm trong các thư mục `node_modules/`, `dist/`, và `build/` ngay cả khi chúng được liệt kê trong `.gitignore`.
